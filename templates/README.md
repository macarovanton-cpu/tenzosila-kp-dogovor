# templates/kp_template.docx — DOCX-шаблон КП

Шаблон собирается из эталонного КП Гипсобетон через `make_template.py`
и используется для генерации коммерческих предложений через `docxtpl`.

---

## Список плейсхолдеров (14 статических + 3 в цикле)

### Шапка (стр. 1)

| Плейсхолдер      | Описание                          | Пример                    |
|------------------|-----------------------------------|---------------------------|
| `client_name`    | Получатель КП                     | `АО Гипсобетон`           |
| `kp_number`      | Номер КП                          | `47141`                   |
| `kp_date`        | Дата КП (ДД.ММ.ГГГГ)             | `22.04.2026`              |

### Технические характеристики (стр. 3)

| Плейсхолдер              | Описание                                      | Пример                                      |
|--------------------------|-----------------------------------------------|---------------------------------------------|
| `warranty_text`          | Срок гарантии (ячейка «Гарантия»)             | `36 месяцев`                                |
| `division_info`          | Описание весов (ячейка «Описание весов»)      | `Весы автомобильные ВЕСТА-С-80-18, max 80т, ...` |
| `max_load_t`             | Максимальная нагрузка, т                      | `80`                                        |
| `platform_size`          | Габариты платформы, м                         | `18×3`                                      |
| `main_scale_label`       | Цена поверочного деления, кг                  | `20 до 60т / 50 от 60т до 80т`             |
| `construction_description` | Конструкция платформы                       | `Конструкция сплошная 09Г2С: Двутавр...`   |

### Динамическая спецификация (spec_items)

Таблица спецификации использует jinja-цикл `{%tr %}`. В контекст передаётся список словарей:

```python
"spec_items": [
    {"name": "Весы автомобильные ВЕСТА-С-80-18, max 80т, р-р платформы 18х3м",
     "price": "2 450 000", "term_days": "45"},
    {"name": "Фундамент под ВЕСТА-С/Ф, 18м, «под ключ»",
     "price": "1 900 000", "term_days": "30"},
    # ... произвольное число позиций
]
```

| Поле словаря  | Описание                           | Тип    |
|---------------|------------------------------------|--------|
| `name`        | Наименование позиции               | `str`  |
| `price`       | Цена, руб. (строка с пробелами)    | `str`  |
| `term_days`   | Срок исполнения, рабочих дней      | `str`  |

Строка ИТОГО ниже таблицы — статическая, её плейсхолдер `total_price` работает вне цикла.

| Плейсхолдер       | Описание                              | Пример      |
|-------------------|---------------------------------------|-------------|
| `total_price`     | ИТОГО, руб.                           | `5 930 000` |
| `total_term_days` | Срок исполнения для ИТОГО, раб. дней  | `35`        |
| `vat_percent`     | Ставка НДС, %                         | `22`        |

### Условия поставки

| Плейсхолдер      | Описание                      | Пример                                        |
|------------------|-------------------------------|-----------------------------------------------|
| `payment_line_1` | Строка предоплаты             | `Предоплата: 50% от стоимости проекта`        |
| `payment_line_2` | Строка доплаты (+ монтаж)     | `Доплата: 50% по завершении проекта`          |

## Как регенерировать шаблон из исходника

```bash
# Из корня проекта:
python src/generators/make_template.py
```

**Что делает скрипт:**
1. Открывает `03_knowledge_base/sample_kps/Гипсобетон_ВЕСТА-С-80-18.docx`
2. Схлопывает разбитые Word-ом runs в целевых ячейках (Цена деления, ИТОГО и др.)
3. Заменяет 14 статических значений на `{{ placeholder }}`
4. Преобразует таблицу спецификации под jinja-цикл `{%tr for item in spec_items %}`
5. Удаляет блок «Спецификация ПАК ОРИОН» (стр. 5)
6. Сохраняет результат в `templates/kp_template.docx`

Скрипт **идемпотентен** — повторный запуск перезаписывает шаблон с тем же результатом.

## Известные ограничения (MVP)

1. **Динамическая спецификация через jinja-цикл `{%tr%}`**: поддерживается
   произвольное число позиций. Минимум — 1 позиция (автовесы), максимум — ограничен
   только здравым смыслом. Протестировано до 12 позиций.

2. **Блок «Спецификация ПАК ОРИОН» удалён** из шаблона. Если нужна подробная
   расшифровка состава ОРИОН — добавить с условным блоком `{% if price_orion != '—' %}`.

3. **Температурный диапазон захардкожен** под дефолтную комплектацию:
   датчик Zemic DHM9B (`-30…+40 °C`) + терминал ТИТАН 3ЦС (`-0…+40 °C`).
   Для нестандартных датчиков потребуется отдельный плейсхолдер.

4. **`payment_line_2` — одна строка**. В расщеплённой схеме оплаты (Кирова)
   третья строка («За монтаж: ...») включается в `payment_line_2` через точку с запятой.
   Разбивка на 3 строки — в backlog.

5. **`division_info`** — плоская строка, без переносов. В MVP не поддерживает
   многострочный вывод внутри ячейки таблицы через `docxtpl`.

6. **Оглавление (TOC) не обновляется автоматически.** После удаления блока ПАК ОРИОН
   номера страниц в автоматическом оглавлении устарели относительно реальной пагинации.
   При открытии сгенерированного КП в Word нужно обновить TOC вручную:
   ПКМ по оглавлению → «Обновить поле» → «Обновить целиком».
   Автоматическое обновление через `settings.updateFields` — в backlog.
