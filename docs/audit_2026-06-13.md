## P1 — Критические (юридические данные, тихие ошибки)

- [ ] **Ложный адрес из числовых строк** `requisites_parser.py:259`  
  Любая строка с 6+ цифрами считается адресом.  
  Риск: `parse_requisites("ИНН 7707083893")` заполняет `ЗАКАЗЧИК_АДРЕС_ЮР = "ИНН 7707083893"`. То же для строк `БИК ...`, `КПП ...`, `р/с ...`.  
  Триггер: блок реквизитов где ИНН/счёт идут отдельной строкой без якоря-подписи.

- [ ] **Телефон из расчётного счёта** `requisites_parser.py:57`  
  Телефонный regex не привязан к границам поля, матчится внутри р/с.  
  Риск: `р/с 40702810938000060473` → `ЗАКАЗЧИК_ТЕЛЕФОН = "81093800006"`.  
  Триггер: р/с начинается на `4070281...` или другую последовательность похожую на `8(xxx)xxx-xx-xx`.

- [ ] **ФИО директора подменяется главбухом** `requisites_parser.py:308/319/325`  
  После якоря `директор` берётся первое ФИО в окне 200 символов, даже если оно из следующей строки с другой должностью.  
  Риск: `Генеральный директор\nГлавный бухгалтер Петрова Мария Ивановна` → директор = `Петрова Мария Ивановна`.  
  Триггер: карточка где директор без ФИО на той же строке, а следом идёт главбух/контакт.

- [ ] **КПП с префиксом 04 перебивается в БИК** `requisites_parser.py:205`  
  9 цифр с префиксом `04` всегда пишутся в БИК, даже при явном якоре `КПП`.  
  Риск: `КПП 040101001` → `ЗАКАЗЧИК_БИК = "040101001"`, КПП остаётся пустым.  
  Триггер: КПП налоговых органов и некоторых гос. структур начинается на `04`.

## P2 — Важные (редкие конфигурации, нечётные суммы)

- [ ] **Ложная ошибка «перебор процентов» при одинаковых базах** `payment_lines_editor.py:159/179`  
  Split-строки группируются по числовому значению `База, ₽`, а не по смыслу бакета.  
  Риск: весы и фундамент по 1 000 000 рублей → базы совпадают → строки склеиваются → валидный split 40/60 даёт ложный `Σ% > 100%`.  
  Триггер: стоимость весов == стоимость фундамента.

- [ ] **Перебор процентов проходит молча через round** `payment_lines_editor.py:164/187`  
  Проверка использует `round(sum_pct)`.  
  Риск: `60.2% + 40.2% = 100.4%` проходит как 100%. Редактор может добить последнюю строку до базы, давая сумму строк > ИТОГО.  
  Триггер: проценты с десятичными, сумма которых на 0.x% превышает 100.

- [ ] **Перебор суммы на 1 рубль не ловится** `payment_lines_editor.py:195/196`  
  Проверяется только недобор, перебор суммы строк вообще не ловится.  
  Риск: нечётные суммы + split 17/83 → сумма строк = ИТОГО+1 руб, ошибки нет.  
  Пример: базы 1 000 001 и 1 000 002, split 17/83 → сумма строк 2 000 004 при ИТОГО 2 000 003.

- [ ] **Потеря предоплаты фундамента/доставки при нулевом проценте весов** `payment_line.py:268/300`  
  Строка добавляется по управляющему проценту весов (`s_prepay`/`s_post`), хотя сумма может быть ненулевая из фундамента или доставки.  
  Риск: `scales.prepay = 0`, `foundation.prepay > 0` → предоплата фундамента теряется. `scales.postpay = 0`, `delivery.postpay > 0` → доставка теряется.  
  Триггер: нестандартная схема где весы без предоплаты, но фундамент с предоплатой.

- [ ] **v2_preship=0 заменяется дефолтом 40** `payment_line.py:107`  
  `v2_preship = 0` заменяется дефолтом `40` из-за конструкции `or 40`.  
  Риск: менеджер выставил 0% перед отгрузкой в КП, snapshot сохранил 0, но договорные строки строятся как 40%.  
  Триггер: v2-пресет где preship = 0 (двухфазная оплата без среднего платежа).

## P3 — Низкий приоритет (граничные случаи, нет реального триггера)

- [ ] **Temp-файл не удаляется при падении fill_template** `compose.py:49/55`  
  `_attach_*` добавляется в `tmp_files` только после успешного `fill_template`. Если `fill_template` сохранил файл но упал на textbox XML — временный `_attach_*.docx` остаётся на диске.  
  Риск: замусоривание `output/contracts/`, не функциональный.

- [ ] **merge_runs guard только на w:drawing** `filler.py:29/43/65`  
  Guard защищает `w:drawing`, но `run.text = ...` также может стереть `w:pict`, `w:object`, field-runs (`w:fldChar`, `w:instrText`) и прочее non-text содержимое.  
  Риск: в текущих шаблонах таких элементов нет, но при добавлении новых приложений с полями/объектами — риск потери содержимого без предупреждения.
