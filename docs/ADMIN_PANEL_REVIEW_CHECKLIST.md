## Модель Sonnet vs Opus

- **Opus всегда:** Задача 5 — atomic-запись + edge-кейсы сбоя.
- **Задача 2:** Opus только если разведка R3 показала грязный вывод pdfplumber; иначе Sonnet.
- **Остальные:** Sonnet.

## Проверки перед push (любая задача с кодом)

- [ ] `pytest tests/admin/ -v` — зелёный
- [ ] UI-задачи (8, 9, 10): `streamlit run` — глазами
- [ ] Задача 5: round-trip формата проходит
- [ ] `git diff --name-only` — не залезли в `src/contracts/` или схему `prices.json`

## Не автоматизировать полностью (финальная проверка человеком)

**Парсеры (задачи 2, 3) и применение (задача 8):** обязательный просмотр результата на реальных
PDF/прайсе, не только зелёные тесты.

> Цена ошибки = неверная цена в КП.

## Что может сломать проект

- Изменение формата `prices.json` или ключей моделей/опций
- Правка `contracts/extractor.py`
- Кэш чтения прайса без сброса при записи (R4)
