### Что уже есть в session_state (берём напрямую)

| Поле договора | Ключ session_state | Преобразование |
|--------------|-------------------|----------------|
| Дата договора | `kp_date` (date) | `strftime`, `format_date_parts()` |
| Номер договора | `kp_number` (str) | Прямо |
| Модель краткая | `model_id` (str) | `"vesta-с-60-18"` → `"ВЕСТА-С-60-18"` |
| Макс. нагрузка | `model_max` (int) | `str()` |
| Итого с НДС | вычислить: `calc_totals(spec_items)["with_vat"]` | `format_amount()` |
| Итого прописью | то же число | `utils_ru.number_to_words()` |
| Ставка НДС | `config.VAT_RATE` | `str(int(0.22 * 100))` → «22» |
| Сроки | `term_days_per_item` | По ролям: scales/foundation/install/delivery/verification |
| Суммы по группам | `spec_items` | Суммировать по `payment_group` |
| Условия оплаты | `payment_preset_id` + payment state | Конвертер (см. ниже) |

### Что отсутствует — нужно добавить в UI

| Поле | Тип | Рекомендация |
|------|-----|-------------|
| `ЗАКАЗЧИК_*` (19 полей) | Реквизиты | Expander «Реквизиты заказчика» + опциональная загрузка карточки DOCX |
| `СПЕЦ_АДРЕС_ОБЪЕКТА` | str | Текстовое поле в том же expander (можно пустым) |

### Конвертер условий оплаты (СПЕЦ_ОПЛАТА_П1..П6)

Обязательный формат каждой строки:
```
AMOUNT (WORDS) рублей в т.ч. НДС 22% — DESCRIPTION
```
Пример: `283 500 (двести восемьдесят три тысячи пятьсот) рублей в т.ч. НДС 22% — предоплата`

| Пресет (`payment_preset_id`) | Генерируемые строки |
|------------------------------|---------------------|
| `v1` (аванс % + постоплата) | П1=предоплата X%, П2=постоплата |
| `v2` (аванс + предотгр + пост) | П1=аванс, П2=предотгрузочная, П3=постоплата |
| `v3` (100% постоплата) | П1=100% постоплата с указанием триггера |
| `prepay_100` | П1=100% предоплата |
| `split_by_items` | По группам: весы, фундамент, доставка, монтаж+поверка |
| `custom` | П1=`payment_custom_text` как есть |

2. Настроить конфигурацию: модель ВЕСТА-С-60-18, опции, оплата V1 50%
3. Ввести тестовые реквизиты (из `test_data/карточка_ЛСЗ.docx`)
4. Нажать «Сформировать договор и спецификацию»
5. Скачать оба DOCX, открыть в Word
6. Проверить: ни одного `{{...}}` не осталось
7. Проверить: `СПЕЦ_ИТОГО_ПРОПИСЬ` соответствует числу `СПЕЦ_ИТОГО`
8. Проверить: условия оплаты сходятся в 100% итога
9. Проверить подписи в конце спецификации (8 реквизитных полей)

## Быстрая справка: функции из копируемых модулей

### filler.py
- `fill_template(template_path, data, output_path)` — основная функция заполнения
- `get_unfilled_placeholders(docx_path)` — список незаполненных `{{...}}`
- `remove_empty_paragraphs(doc_path, output_path)` — удалить пустые строки после заполнения

### utils_ru.py
- `number_to_words(n: int) -> str` — «два миллиона восемьсот тридцать пять тысяч»
- `format_date_parts(date_str: str) -> dict` — `{"day": "15", "month": "марта", "year": "2026"}`
