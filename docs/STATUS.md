## Результат codex review (2026-06-14)

Review выполнен после стабилизационного пакета. Критических P1 не найдено, но есть 1 P2 по платежному редактору и 2 замечания по артефактам/фикстурам.

### Findings

**P2 — `src/ui/payment_lines_editor.py:146` — группировка процентов завязана на редактируемый текст `Объект`.**

Новая группировка процентов использует отображаемый/редактируемый текст объекта. Из-за этого перебор по одной и той же базе можно обойти разницей в названии: например, две строки по 80% от базы `1 000 000`, но с объектами `Весов` и `Весы`, не дают blocking error, а только warning по недобору общей суммы. Это конфликтует с правилом: «перебор по базе >100% → error». Нужно группировать по стабильному `bucket/source id`, а текст оставить только для отображения.

Статус: **открыто, P2, не блокирует тег v2.2 при ручном smoke, но обязательно к исправлению до активной раздачи коллегам.**

**P2 — `docs/synthetic_test_run.txt` — synthetic e2e baseline не подтверждён.**

Синтетические DOCX/PDF-фикстуры изменены, но сохранённый прогон показывает `5/5 failing e2e cases`. Это уже числится в техдолге как известные падающие synthetic e2e, но текущие fixture-изменения нельзя считать подтверждённым baseline-обновлением, пока synthetic e2e не приведён к ожидаемому состоянию.

Статус: **открыто, P2 для тестового baseline, не блокирует ручной smoke реального Streamlit-флоу.**

**P3 — `docs/supply_payment_preview.txt` — файл невалиден как UTF-8 для стандартных инструментов.**

PowerShell файл читает, но `rtk read` падает с `stream did not contain valid UTF-8`. Если preview остаётся в репозитории как документация/артефакт ревью, его нужно пересохранить в UTF-8, чтобы стандартные инструменты чтения и поиска не спотыкались.

Статус: **открыто, P3, косметика/инструментальная совместимость.**

## Известные ограничения (закрываются позже)

- ОРИОН-приложения не реализованы как полноценный пакет документов.
- Контрольный лист: только пандусный и приямок.
- `монолитная_плита`: без строительного задания — нет унифицированных чертежей.
- Нумерация приложений всё ещё требует внимательного ручного контроля на нестандартных сценариях.
- Supply-флоу использует второй движок рендеринга (`docxtpl/Jinja`), поэтому при будущих изменениях шаблонов нужна отдельная проверка плейсхолдеров.
