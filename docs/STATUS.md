## Очередь фаз

0. **Гейт менеджеров** ← активный фронт (см. выше).
1. **Ф0 — порт `core/`.** P0-05 (каркас + стражи границ) сделан → P0-06
   (развязка секретов, `core/settings.py`, env-only) → P0-07…P0-20.
   Автономные пачки строго под golden-gate: те же входы → новый бэкенд → дамп
   совпадает с эталоном; эталон меняется только через freeze, отдельным
   коммитом с причиной (§2.4 MIGRATION_PLAN).
2. **P0-21 — единый LLM-слой** (`core/shared/`, спека `docs/TENDER_PLAN.md` §5.1:
   вилка Anthropic SDK / OpenRouter, structured output, ретрай). Экстрактор
   реквизитов переписывается на него при переносе, не отдельным фронтом
   (остаток A4 — см. TECH_DEBT).
3. **Ф1 — оболочка портала + КП.** Левое меню модулей + рабочая область,
   Bitrix-подобный стиль, AntD-токены; фронт КП — эталон стиля.
4. **Ф2 — договоры.** 5. **ФТ — тендеры.** 6. **Ф3 — консолидация**
   (свой Postgres, админка, удаление Streamlit, Bitrix24, агентный слой,
   остаток техдолга).

Вне очереди (ручная работа, кода не касается): **ФТ-03 — golden-корпус
тендеров.** 4-5 реальных комплектов + разметка эталонов, ~2 часа. Хранится
вне репо (данные заказчиков) — локальная папка + путь в env.

**Правило очереди:** один активный фронт за раз. Течёт в проде → чиним;
не течёт → строим дальше. Исключение — read-only диагностика, не
пересекающаяся по файлам с активным фронтом.
