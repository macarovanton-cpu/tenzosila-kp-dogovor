## Что закрыто за эту сессию

**P1 — краш редактора оплаты (widget key conflict):**
- Причина: platform_width_m сидился в state.py И передавался как default= виджету
  segmented_control — Streamlit это запрещает.
- Фикс: убран default= и write-back ветка в model_section.py; источник стартового
  значения — сид в state.py. Мёртвая ветка внешнего dict удалена. 594 passed.

**P2 — оплата: bridge расширен на не-split пресеты:**
- build_lines_from_snapshot теперь маппит v1/v2/v3/prepay_100 в PaymentLine
  с каноническими триггерами (раньше возвращал [] для всего кроме split_by_items).
- Маппинг: v1 → SPEC_SIGNED/WORK_ACT; v2 → +SHIPMENT_READY; v3 → DELIVERED или
  WORK_ACT по trigger_id; prepay_100 → SPEC_SIGNED. custom остаётся [].
- База не-split строк = ИТОГО спецификации, share_object = «общей цены договора».
- Решение подтверждено анализом 25 реальных спецификаций: канонические тексты
  PaymentTrigger дословно совпадают с формулировками в спеках. kind расширен
  значением «оплата» (для v3 постоплаты).

**Редактор оплаты — переделка на «процент-истина» (вариант B):**
- Процент и База редактируемые, Сумма производная (amount = round(%×база), read-only).
- PaymentLine получил поле base_amount; bridge проставляет базу (не-split = ИТОГО,
  split = по бакетам: L1=весы+фундамент, L2=фундамент, L3=весы+доставка, L4/L5=iv).
- Видимая read-only колонка «База, ₽» (объясняет разные суммы при равных %).
- Валидация по процентам, не по рублям: перебор по базе >100% → st.error (жёстко),
  недобор до ИТОГО → st.warning (мягко). Старый мигающий ruble-error удалён.
- Forced rerun на изменении + идемпотентность recompute (защита от зацикливания).
- Удаление строк — нативное (выделить + Delete в data_editor).

**P2 — читаемые имена приложений в UI:**
- pretty_name(path) в fundament_lookup.py: технические имена → человеческие
  («Пандусный фундамент 440 мм (С/Ф), 3 секции» и т.п.). selectbox показывает
  читаемый label, в attachments сохраняется Path.
