## Очередь

1. **A4 — фикс `extractor.py`** ← активный фронт. LLM с правом пересчитывать суммы
   и догадываться работает в проде. Минимальный фикс (промт + 2 места в коде),
   полный редизайн — при переносе в `core/` (см. п. 3).
2. **Ф0 — порт `core/`:** P0-05 (каркас по границам Д-2) → P0-06…P0-20.
   Автономные пачки под golden-gate. Streamlit продолжает работать на `core/` (И-5).
3. **P0-21 — единый LLM-слой** `core/shared/llm_client.py` по спеке `TENDER_PLAN.md` §5.1
   (вилка Anthropic SDK / OpenRouter, structured output, ретрай). Экстрактор реквизитов
   переписывается на него ПРИ ПЕРЕНОСЕ, не отдельным фронтом.
4. **Ф1 — оболочка портала + КП.** Дизайн (левое меню модулей + рабочая область,
   Bitrix-подобный стиль, AntD-токены) → фронт КП становится эталоном стиля.
5. **Ф2 — договоры.** 6. **ФТ — тендеры.** 7. **Ф3 — консолидация** (свой Postgres,
   админка, удаление Streamlit, Bitrix24, агентный слой, остаток техдолга).

**Можно делать заранее, вне очереди (ручная работа, кода не касается):**
**ФТ-03 — сбор golden-корпуса тендеров.** 4-5 реальных комплектов (чистый PDF, скан,
DOCX+XLSX-микс, многопозиционный) + разметка эталонных канонических форм. ~2 часа.

## Известные ограничения (не баги — принятый MVP-скоуп)

- `named_form`/`ИМЕНУЕМ`: Колхоз/Компания/Фирма → «именуемое».
- Между двумя таблицами docx нужен ≥1 абзац-разделитель.
- ОРИОН-приложения (Шаг 10) — не пакет документов. Контрольный лист: только пандусный
  и приямок. `монолитная_плита`: нет унифицированных чертежей.
- Supply-флоу на docxtpl — отдельная проверка плейсхолдеров при смене шаблонов.
- Автовыбор типа договора — подсказка-дефолт, выбор ручной.
- Ручные позиции «Прочее» — строка + оплата, без клауз. Монтаж — выбирать тип «Монтаж».
