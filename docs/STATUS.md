- **Per-item срок исполнения с vMerge в spec-таблице DOCX** (29 апреля, commit `3911311`). Параллельная модель: T_фиксированных = монтаж(3) + поверка(1) + доставка(1). Весы + scales-aux опции (рама/ограждение/пандусы) сливаются по vMerge в одну ячейку.

- **Per-role сроки + динамический лейбл фундамента/рамы/пандусов** (29 апреля, commits `3c4bc67`, `087fabe`). Новая модель сроков заменяет параллельную T_остаток. TERM_DAYS_DEFAULTS: scales=20, orion=5, foundation=10, canopy=25, install=3, delivery=1, verification=1. VARIABLE_ROLES скейлятся пропорционально при правке T_общий, FIXED_ROLES остаются неизменными. `resolve_dynamic_option_label` подменяет групповое обозначение в лейблах foundation_*, frame_*, ramp_*.

- **Регресс-фиксы DOCX + переделка модели оплаты v0.4** (29 апреля, commit `5795c15`):
  - vMerge: чистка `<w:vMerge>` на loop-template-row в transform_spec_table
  - PT Sans 11pt: применяется к ячейкам Tbl 2 row 1 (диапазон температур)
  - dyn-labels рам и пандусов в UI: `resolve_dynamic_option_label` применяется к labels чекбоксов
  - **Переделка оплаты v0.4:** удалены 4 устаревших пресета (50/50, 30/70, postpay_15d, postpay_30d). Добавлены 3 новых варианта через `st.radio`:
    - **V1** «Аванс N% + Постоплата (100−N)%» — постоплата автосчитается через `st.metric`
    - **V2** «Аванс A% + Перед отгрузкой B% + Постоплата (100−A−B)%» — postpay derived
    - **V3** «100% постоплата через N дней» с выбором точки отсчёта (после доставки / монтажа / акта)
  - prepay_100, split_by_items, custom — без изменений
  - В split_by_items добавлена кнопка «Применить ко всем группам»
  - Validation: V1 prepay∈[1,99]; V2 prepay+preship≤99; V3 days≥1

- **Расширение sensor/indicator alternatives в UI до 10 датчиков и 4 терминалов** (29 апреля, commits `2433ce9`, `3c3e9b2`):
  - Датчики: Zemic DHM9B, Zemic DBM14G, Zemic HM9B, Zemic BM14G, Keli ZSFY, Keli ZSFY-D, HBM C16A, HBM C16i, МВ-150 (9 моделей)

  - Удалены: Mera CDL, Keli WBK, ТИТАН 3Ц, DIS2116, i 30 (не используются в продажах)
  - Технические данные (IP, температуры) — из `equipment_specs.json` через `data_loader.get_equipment_info`

- **V1/V2 number_input на старте показывают дефолт state, не min_value** (29 апреля, commit `95b9c18`). Streamlit-квирк: при первом рендере виджета без явного `value=` Streamlit падает на `min_value=1`. Фикс: `value=int(st.session_state.get("payment_v1_prepay", 50))`.

## ⚠️ Известные ограничения / технический долг

- **Дублирование данных оборудования.** UI читает датчики/терминалы из `models.json["equipment_defaults"]["sensor"]["alternatives"]`. Технические данные (IP, температуры, рег. номера) — из `equipment_specs.json`. Списки сейчас синхронизированы вручную (10 датчиков, 4 терминала). При следующем расширении надо править оба файла. **Закроется в архитектурном рефакторинге B.**
- **Visual regression baseline устарел** после правки шаблона (page breaks). Обновить когда дойдём до Streamlit Community Cloud (там visual regression менее критичен — KP делается на проде, не в e2e).
- **Chromium для e2e не установлен в Codespace** — Playwright тесты прогоняются только локально на Windows.
- **40-тонные модели** в прайсе отсутствуют. Уточнить у производства.
- **Линейка П-80** — цены скопированы с П-100, `data_incomplete: true`.
- **Усиленные пандусы для П** — нет в прайсе.
- **Навес 24м** — `on_request: true`.
- **IP-рейтинги датчиков** — 13/16 моделей с `ip_rating: null` (в ОТ не указано). В DOCX выводится «Не заявлено».
