## Что закрыто за эту сессию (2026-06-12)

**P1: Падение редактора оплаты (widget key conflict) — ЗАКРЫТ:**
- Причина: `platform_width_m` сидился в session_state (state.py) И передавался
  как `default=` в segmented_control — Streamlit это запрещает, отсюда краш при
  rerun (триггерился взаимодействием с редактором оплаты в Договоре).
- Фикс (вариант A): убран `default=` у виджета, убрана мёртвая ветка write-back
  `if state is not st.session_state`. Источник дефолта — сид в state.py.
- Подтверждено: единственный call-site render_model_section — КП-страница со
  st.session_state. 594 passed.

**P2: Оплата не адаптируется (bridge возвращал []) — ЗАКРЫТ:**
- Разобрано по 25 эталонным спецификациям: канонические триггеры PaymentTrigger
  дословно совпадают с формулировками реальных спек. Модель достаточно
  выразительна, расширять не нужно.
- bridge build_lines_from_snapshot расширен на не-split пресеты:
  v1 (SPEC_SIGNED/WORK_ACT), v2 (+SHIPMENT_READY), v3 (DELIVERED/WORK_ACT по
  trigger_id), prepay_100 (SPEC_SIGNED). custom → [] (свободный текст, корректно).
- База не-split строк = ИТОГО спецификации, share_object = «общей цены договора»
  (не привязка к бакетам — это отличие от split_by_items).
- Добавлен kind «оплата» + share_prep «от». Сумма строк добирается остатком на
  последней строке = ИТОГО.

**Редактор оплаты — переделка на «процент истина, сумма производная»
(вариант B) — ЗАКРЫТ:**
- Колонка «База, ₽» (видимая, для не-split = ИТОГО, для split = бакет),
  «Сумма, ₽» — read-only производная (amount = round(pct/100 × base)).
- Устранён рассинхрон таблица↔предпросмотр (forced rerun on change,
  идемпотентный recompute, строгие python-типы против бесконечного rerun).
- Валидация переделана: перебор по базе >100% → error; недобор до ИТОГО →
  warning; точное совпадение → caption. Убран мигающий ruble-error.
- Поймано Opus'ом: комбинированные split-строки (share_pct=None) не
  пересчитываются, сумма из bridge сохраняется.

**Шаг 9 — docxcompose-склейка спецификации с приложениями — ЗАКРЫТ
и подтверждён вручную:**
- Новый модуль src/contracts/compose.py: compose_spec_with_attachments читает
  готовые пути из contract["attachments"], заполняет плейсхолдеры приложений,
  склеивает: Спецификация → Приложение №1 (build_task) → №2 (control_sheet).
- Inline-заглушка приложения удалена из spec_v2.docx (patch_spec_v2_template.py),
  удалён {{APPENDIX_FOUNDATION_CHECK}} и мёртвый код _render_foundation_check.
- Зависимость docxcompose добавлена.
- **Критический баг по ходу — merge_runs уничтожал чертежи:** fill_template
  вызывал `run.text = ""` на ранах с w:drawing → python-docx clear_content()
  удалял drawing → 14 чертежей build_task превращались в 0 (пустые страницы).
  Фикс: guard в merge_runs (filler.py) — не трогать раны с w:drawing.
  Подтверждено: build_task снова 7-8 страниц с чертежами.
- **Разрывы страниц:** docxcompose сам section break не вставляет → каждое
  приложение получает явный разрыв перед склейкой. Приложения начинаются с
  новой страницы, без пустых страниц между блоками.
- Диагностика причины merge_runs — образцовая, на уровне XML (8 PNG, 14 drawing,
  blip refs до/после). Гипотеза model_code=None была опровергнута DIAG-выводом
  до того как чинить — причина доказана, не предположена.
