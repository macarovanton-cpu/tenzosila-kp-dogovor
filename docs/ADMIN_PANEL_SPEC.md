# Админ-панель прайса — продуктовая и UX-спецификация (Фаза 1)

## Контекст

Внутренний инструмент Тензосилы: конфигуратор КП и генератор договоров по автовесам ВЕСТА.
Пользователи админки: менеджер по продажам и руководитель отдела продаж (РОП). Без разработчика
в цикле обновления. Язык интерфейса — бизнесовый, не технический.

## Реальный вход — PDF, не JSON

Источник прайса — два текстовых PDF (OCR не нужен):

- **Дилерский:** модели ВЕСТА (пара розница/дилер) + железные опции. Парсится механически.
- **Розничный:** услуги/фундаменты/монтаж (стр. 3), ОРИОН (стр. 4), навесы (стр. 19). Плоские таблицы.

`data/prices.json` — внутренний формат хранения (результат извлечения), **НЕ** пользовательский вход.

## Scope Фазы 1 (что входит в прайс)

| Категория | Источник | Цена | Вариантов |
|-----------|----------|------|-----------|
| Модели ВЕСТА (линейки ФЛ/СЛ/Ф/С/П/СБ) | Дилерский | вилка розница/дилер | ~59 |
| Железные опции (пандусы, рамы, ограждения, люки, закладные, резина) | Дилерский | вилка | ~18 |
| Услуги/фундаменты/монтаж | Розничный стр. 3 | одна цена | ~16 |
| Навесы под ВЕСТА | Розничный стр. 19 | одна цена | ~10 |
| ОРИОН (5 уровней × оборудование+шеф-монтаж) | Розничный стр. 4 | одна цена | 10 |

**ОРИОН** — помечены флагом `individual_calc`. Справочные, парсятся, но не для автоподстановки.

**Спецзначение «по запросу»** — отдельный признак, **НЕ** ноль.

## Вне scope Фазы 1

- Мобильные ВЕСТА-М1/М2
- Вся остальная номенклатура (РЕУС, ВЕКТОР, КРАБ, поосные, животноводческие)
- Матрица моделей со стр. 2 розницы (модели берём из дилерского)
- LLM-извлечение (не используется)
- Коэффициенты ценовой вилки (Фаза 2)

## Пользовательский сценарий

Один экран «Прайс», три состояния: **смотрю → готовлю изменение → применяю**.

---

### Главный экран / обзор

Карточка текущего прайса бизнес-языком:
- Дата (`valid_from`), источник (2 PDF)
- Счётчики по типам (модели / опции / услуги / ОРИОН)
- Число предупреждений

Кнопки:
- **[Обновить прайс]**
- **[Откатить на предыдущую версию]** — неактивна без бэкапа

Сворачиваемый блок «Технические детали» — туда `price_class`, имена полей, сырая диагностика.

---

### Загрузка PDF

После [Обновить прайс] — выбор источника:
- **[Загрузить из PDF]** — два слота: дилерский, розничный
- **[Редактировать текущий]**

При парсинге — спиннер «Читаю прайс…».

**Защита:** файл не PDF / не тот прайс / мало строк → понятное сообщение, не трейсбек, предложение проверить таблицу вручную.

---

### Режим «Редактировать текущий»

Рабочая таблица наполняется копией живого `prices.json`, PDF не нужен. Дальше тот же поток.

Назначение — точечная правка (опечатка, новая цена одной позиции).

---

### Таблица распознанных строк

| Наименование | Тип | Розница | Дилер | Признак | Источник |
|---|---|---|---|---|---|

- У услуг поле «Дилер» серое.
- «По запросу» — бейдж, не пустая цена.

**Действия человека:** правка ячеек, добавление строк (потерянное парсером или отсутствующее в PDF), удаление, отметка «по запросу».

**Защита:** подсветка подозрительного:
- 0-цена не у «по запросу»
- Розница < дилера
- Дубль
- Нераспознанное

---

### Ошибки и предупреждения

Кнопка **[Проверить]** делит результат на:

- **БЛОКЕРЫ (красное):** пустая/нулевая цена не у «по запросу»; розница < дилера; дубль ключа.
- **ПРЕДУПРЕЖДЕНИЯ (жёлтое):** новая позиция; неполные данные; стало «по запросу».

При наличии хотя бы одного блокера применение недоступно.

---

### Бизнес-сводка изменений

К текущему прайсу, сгруппировано:

| Группа | Что показываем |
|--------|---------------|
| Подорожало | было → стало, % |
| Подешевело | было → стало, % |
| Добавлено | новые позиции |
| Удалено | **всегда подсвечено** (частая причина — потеря строки парсером) |
| Стало «по запросу» | позиции с изменением признака |

«Изменений нет» — если их правда нет.

---

### Подтверждение, бэкап, откат

- **[Применить новый прайс]** — активна только при 0 блокеров.
- По нажатию: текущий прайс → бэкап, затем atomic-запись нового, сообщение об успехе.
- **Откат:** кнопка на главном экране возвращает бэкап. Один уровень. С подтверждением «вернуть прайс от <дата>?».

---

### Чего интерфейс НЕ делает

- Не пишет втихую
- Не применяет с блокерами
- Не трогает модели / clauses / шаблоны
- Не ходит в сеть / LLM
