# Разведка: формулировки блока оплаты (2026-07-09)

Read-only карта. Ничего не менялось, фиксы не предлагаются — только что звучит
сейчас, что в эталоне, где разрыв.

Сценарий сравнения везде один: **весы + фундамент + монтаж + поверка + доставка**
(без ОРИОН), на **дефолтных процентах системы** (`data/payment_terms.json`,
пресет `split_by_items`: scales 50/50, foundation 50/50, delivery 0/100,
installation_and_verification 0/100).

## 1. КП — `render_payment_block` / `render_split_by_items`

Код: `src/generators/payment_renderer.py:33-88` (точка входа —
`render_payment_block:136-163`).

Дословные f-строки шаблонов (ровно 4 возможные строки, порядок фиксирован):

```python
# строка 1 — предоплата
f"— Предоплата: {' + '.join(prepay_parts)}."
# prepay_parts = [f"{pct('scales','prepay')}% {scales_label}"]  (+ фундамент, если есть)
# scales_label = "стоимости весов (включая ПАК ОРИОН)" если есть orion_*, иначе "стоимости весов"

# строка 2 — доплата за весы
f"— Доплата за весы: {' + '.join(postpay_parts)}."
# postpay_parts = [f"{pct('scales','postpay')}% по уведомлению о готовности к отгрузке"]
#                 (+ доставка, если есть)

# строка 3 — доплата за фундамент (только если есть фундамент)
f"— Доплата за фундамент: {pct('foundation','postpay')}% по факту готовности фундамента."

# строка 4 — монтаж и поверка (только если есть монтаж/поверка)
f"— Оплата монтажа и поверки: {pct('installation_and_verification','postpay')}% "
f"по факту выполнения монтажа и поверки."
```

**Важно:** строка 4 читает только `postpay` этой группы. `prepay` группы
`installation_and_verification` в тексте КП не появляется никогда, даже если
он > 0 — код не обращается к этому ключу вообще (`payment_renderer.py:81-86`).

### Пример вывода для сценария (весы+фундамент+монтаж+поверка+доставка, без ОРИОН)

```
— Предоплата: 50% стоимости весов + 50% стоимости фундамента.
— Доплата за весы: 50% по уведомлению о готовности к отгрузке + 100% стоимости доставки.
— Доплата за фундамент: 50% по факту готовности фундамента.
— Оплата монтажа и поверки: 100% по факту выполнения монтажа и поверки.
```

Никаких сумм, слов «НДС», банковских дней, ссылок на «Акт» — текст короткий,
ссылается только на проценты и на общее событие-триггер словами, без юридической
формулы.

## 2. Спецификация договора — `build_lines_from_snapshot` → `format_payment_line`

Код: `src/contracts/payment_line.py` (`TRIGGER_TEXTS:19-26`,
`format_payment_line:44-76`, `build_lines_from_snapshot:240-346`).

Словарь триггеров, дословно:

```python
TRIGGER_TEXTS = {
    SPEC_SIGNED:    "подписания настоящей Спецификации",
    FOUNDATION_ACT: "подписания Акта выполненных работ по строительству фундамента",
    SHIPMENT_READY: "получения уведомления о готовности Весов к отгрузке",
    BRIGADE_READY:  "уведомления о готовности принять монтажную бригаду на месте монтажа",
    WORK_ACT:       "подписания Акта выполненных работ по настоящей Спецификации",
    DELIVERED:      "поставки Весов Заказчику",
}
```

Шаблон строки (ветка с процентом):

```python
share = f"{pct}% {line.share_prep} {line.share_object}"
f"{index}. {kind_cap} {share} в размере {amount_fmt} ({words}) рублей, " \
f"в т.ч. НДС 22%, в течение {line.due} ({due_words}) {line.due_unit} дней " \
f"с момента {trigger_txt}."
```

Ветка без процента (`share_pct is None`, «flat»-формат) — **`share_object`
вообще не печатается**:

```python
f"{index}. {kind_cap} в размере {amount_fmt} ({words}) рублей, " \
f"в т.ч. НДС 22%, в течение {line.due} ({due_words}) {line.due_unit} дней " \
f"с момента {trigger_txt}."
```

`words = number_to_words(amount).strip().capitalize()` — первая буква прописи
**всегда с большой буквы** (`payment_line.py:56`).

### Пример вывода для того же сценария, на дефолтных процентах системы

```
1. Предоплата 50% от стоимости Весов и фундамента Весов в размере
   <сумма> (<Пропись>) рублей, в т.ч. НДС 22%, в течение 5 (пяти)
   банковских дней с момента подписания настоящей Спецификации.

2. Доплата 50% от стоимости фундамента Весов в размере <сумма> (<Пропись>)
   рублей, в т.ч. НДС 22%, в течение 5 (пяти) банковских дней с момента
   подписания Акта выполненных работ по строительству фундамента.

3. Доплата в размере <сумма> (<Пропись>) рублей, в т.ч. НДС 22%, в течение
   5 (пяти) банковских дней с момента получения уведомления о готовности
   Весов к отгрузке.

4. Доплата 100% от стоимости монтажных работ и поверки в размере <сумма>
   (<Пропись>) рублей, в т.ч. НДС 22%, в течение 5 (пяти) банковских дней
   с момента подписания Акта выполненных работ по настоящей Спецификации.
```

Заметки:
- **Строка 3 — flat-формат**, без процента и без объекта, потому что дефолтный
  `scales.postpay=50%` ≠ `delivery.postpay=100%` — правило `if d_post != s_post:
  share_pct_l3 = None` (`payment_line.py:314-315`). Смысл выплаты («Весы и
  доставка») из текста пропадает, остаётся голая сумма.
- **Строки «предоплата монтажа» нет** — `iv.prepay=0` по системному дефолту,
  код добавляет L4-предоплату только если `iv_prepay > 0`
  (`payment_line.py:326-330`).

Доплата 50% от стоимости монтажных работ и поверки в размере … с момента подписания Акта выполненных работ по настоящей Спецификации.» | Спец и эталон дословно совпадают в триггере и в слове «Доплата». КП использует другое слово («Оплата» вместо «Доплата») и не упоминает Акт. |

Сквозной паттерн: **КП** систематически короче и без ссылок на «Акт»; **Спец и
эталон** — единственная пара из трёх источников, где формулировки почти
буквально совпадают (кроме регистра прописи суммы и кейса несовпадающих
процентов весов/доставки).

## 5. Английская терминология — все места

### Видно пользователю (UI)

- `src/ui/payment_section.py:204` — `f"{k}, %"` в форме настройки пресета
  `split_by_items` (мастер КП): поля ввода процентов буквально подписаны
  **«prepay, %»** / **«postpay, %»**, тогда как соседние поля в том же файле —
  на русском («Срок, банк. дней», `payment_section.py:168`).
- `src/ui/payment_section.py:226` — текст подсказки (`help=`) кнопки
  «Применить ко всем группам»: **«Скопировать prepay/postpay из «Весы» в
  остальные активные группы…»** — английские слова прямо внутри русской фразы.

Оба места — в интерактивном превью мастера КП, **не в тексте самого
сгенерированного документа** (КП/Договора).

### Только код/данные — не попадает в текст документов

Ключи `prepay` / `postpay` / `preship`, id пресетов (`v1_prepay_postpay`,
`v2_prepay_preship_postpay`, `prepay_100`), ключ `editable_percent_keys` и т.п.
встречаются как имена переменных/ключей словарей в:
- `src/generators/payment_renderer.py` (параметры `_split_pct`, лямбда `pct`, `render_v1/v2/render_prepay_100`)
- `src/contracts/payment_line.py` (`_DEFAULT_SPLIT_PERCENTS`, `_non_split_phases`, локальные `prepay/postpay/preship`)
- `src/ui/payment_section.py` (заголовок модуля, `_render_prepay_100`, докстринги)
- `src/validation.py` (валидация процентов пресетов v1/v2)
- `src/state.py` (`payment_v1_prepay`, `payment_v2_prepay`, `payment_v2_preship`)
- `src/storage/snapshot_builder.py`, `src/storage/kp_restore.py`, `src/contracts/from_kp.py` (ключи снапшота)
- `data/payment_terms.json` (`default_percents.prepay/postpay`, `editable_percent_keys`)

Построчной проверкой `render_split_by_items` и `format_payment_line`
подтверждено: ни в одну финальную русскую f-строку эти английские ключи не
подставляются — только числа (проценты/суммы) и заранее заготовленные русские
фразы (`TRIGGER_TEXTS`, `scales_label` и т.п.). Единственная лазейка —
свободный ввод в поле «Объект» редактора `payment_lines_editor.py`, если
менеджер сам впишет туда английское слово (ручной ввод, не генерация кода).

## 6. Где КП и Спец расходятся между собой (сверх таблицы вех)

- **Объём и юридические реквизиты.** КП — 4 короткие bullet-строки без сумм,
  НДС, срока и ссылки на Акт. Спец — до 5 пронумерованных пунктов с суммой,
  прописью, «в т.ч. НДС 22%», сроком в банковских днях и точной ссылкой на
  Акт/Спецификацию.
- **Правило объединения групп разное.** КП при объединении групп (весы+фундамент
  в предоплате, весы+доставка в доплате) **всегда** явно печатает обе процентные
  доли через «+». Спец печатает объединённый процент/объект **только если**
  проценты двух групп численно совпадают; если нет — молча уходит в голую сумму
  без процента и без объекта (`payment_line.py:282-283` для предоплаты,
  `payment_line.py:314-315` для доплаты).
- **Монтаж/поверка — разное число строк и разные слова.** КП всегда одна строка
  (использует только `postpay`). Спец — одна или две строки, в зависимости от
  `iv.prepay`. Даже когда обе стороны описывают одну и ту же 100%-ную доплату,
  слова разные: КП — «Оплата монтажа и поверки: N% по факту выполнения…»;
  Спец — «N. Доплата N% от стоимости монтажных работ и поверки… с момента
  подписания Акта выполненных работ по настоящей Спецификации.»
