## Логика последовательности

КП — вход для договоров. Единственная жёсткая связь:
**КП-3 (поля фундамента в snapshot) → Договоры-шаг 8 (библиотека фундаментов).**
Остальное ядро договоров от правок КП не зависит (читает позиции/scope/проценты,
модель платежей КП не меняется). Поэтому блоки можно вести относительно
свободно, соблюдая только эту связь.

Контракт snapshot между чатами фиксируется в HANDOFF.md.

## ФАЗА A — v2.1 + стабилизация КП

### Блок 1 — КП-чат (стабилизируем вход)
1. Маска имени файла: `Компания_Модель_НомерКП_Дата.docx`, кириллица. *(разогрев, Codex/Sonnet)*
2. Нестандартная ширина 3.5/4м + масштаб цены пропорционально. *(формула уточнить)*
3. Шеф-монтаж галкой в поле «Монтаж» → влияет на цену и формулировку.
4. Бытовка (помещение весовщика) с вводом габаритов + произвольные позиции
   (добавил одну → можно вторую), название + сумма вручную.
5. **КП-3 (линчпин): «Фундамент и основание под раму» — 6 вариантов:**
   - Фундамент под весы (модель)
   - Курирование строительства фундамента
   - Фундамент, материалы/спецтехника Заказчика
   - Бетонное основание для весов на раме
   - Укладка дорожных плит
   - Укладка плит ПАГ

   Эмит в snapshot: `foundation_execution`, `foundation_sections`, `model_code`.
   Наименование позиции с типом («…пандусный…» / «…в приямок…»).
6. Платежи «Расщеплённая по позициям»: prepay/postpay → Предоплата/Постоплата,
   автодобор до 100% (модель не меняем, только UX).

### Блок 2 — Договоры-чат (чиним структуру спецификации)
7. Платежи end-to-end: PaymentLine + форматтер + пропись + тесты →
   scope-default скелет → бакеты (3) + фикс id→name → редактор UI. *(шаги 1–4)*
8. Рефактор в сквозную нумерацию, убрать подзаголовки секций. *(шаг 5)*
9. Сроки + зимний вариант секции. *(шаг 6)*
10. clauses.yaml: contractor_supervised + base_type (3 текста) + юр-ревью. *(шаг 7)*

### Блок 3 — Договоры-чат (приложения)
11. Библиотека фундаментов (13 файлов) + lookup секций + UI. *(шаг 8, гейт: КП-3 готов + файлы собраны)*
12. docxcompose-склейка приложений. *(шаг 9)*
13. ОРИОН-приложения (схема размещения + конфигурация ПК). *(шаг 10)*
14. Реквизиты Mode A/B (AI-экстракт + ручной ввод). *(шаг 11)*

**Параллель:** сборку 13 .docx библиотеки (ручная работа в Word) вести во
время блоков 1–2, иначе станет узким местом на шаге 11.

→ Веха A: оба модуля рабочие, v2.1 закрыт.

## Критический путь к цели

Консалтинговая цель = задокументированный завершённый кейс AI-внедрения.
Критический путь — **Фазы A→B**: завершённый, развёрнутый, задокументированный
инструмент = доказательная база. C–E усиливают кейс, но продавать методологию
можно уже после Вехи B.
