# Формат `data/prices.json`

Документ описывает текущий JSON-прайс проекта. Он нужен как референс для
ручной подготовки нового прайса, нормализации, валидации и сравнения версий.

Прайс хранится в `data/prices.json` и загружается как read-only справочник.
Цены указаны в рублях и уже включают НДС 22%.

## Верхний уровень

```json
{
  "_meta": {},
  "models": {},
  "options": {}
}
```

Фактический объём версии `0.4`:

| Блок | Количество |
|---|---:|
| `models` | 45 |
| `options` | 65 |

## `_meta`

Служебный блок с происхождением прайса.

| Поле | Тип | Обязательное | Значение |
|---|---|---:|---|
| `version` | string | да | Версия JSON-формата или набора данных. |
| `source_retail` | string | да | Имя исходного розничного прайса. |
| `source_dealer` | string | да | Имя исходного дилерского прайса. |
| `currency` | string | да | Валюта, сейчас `RUB`. |
| `vat_note` | string | да | Пояснение по НДС и дилерской цене. |
| `valid_from` | string | да | Дата начала действия в формате `YYYY-MM-DD`. |
| `notes` | array[string] | да | Примечания к извлечению и допущениям. |
| `updated_at` | string | да | Дата последнего обновления JSON. |

## Запись модели

Ключ записи в `models` — это `model_id`, например `vesta-фл-60-18`.
Идентификатор может содержать кириллицу и совпадает с id модели из
`data/models.json`.

```json
"vesta-фл-60-18": {
  "retail": 1668432,
  "dealer_ru": 1534958,
  "dealer_discount_pct": 8
}
```

| Поле | Тип | Обязательное | Значение |
|---|---|---:|---|
| `retail` | number | да | Розничная цена модели. |
| `dealer_ru` | number | да | Дилерская цена РФ. |
| `dealer_discount_pct` | number | да | Скидка дилера в процентах. Сейчас 8. |
| `data_incomplete` | boolean | нет | Флаг неполных исходных данных. Сейчас есть у 4 моделей линейки `П-80`. |

Модели используют логику класса A: нижняя граница — `dealer_ru`, дефолт —
`retail`, верхняя граница — `retail × 1.4`. Для нестандартной ширины платформы
цены масштабируются в runtime, но формат JSON от этого не меняется.

## Запись опции

Ключ записи в `options` — стабильный `option_key`, например `ramp_set_f_s` или
`install_default`.

Базовая форма:

```json
"ramp_set_f_s": {
  "label": "Комплект пандусов под весы ВЕСТА-Ф/С (L=3,9м)",
  "applies_to_lines": ["Ф", "С", "П"],
  "applies_to_lengths": [16, 18, 20, 22, 24],
  "price_retail": 380000,
  "price_dealer_ru": 349600,
  "discount_pct": 8,
  "price_class": "A_retail_and_dealer"
}
```

| Поле | Тип | Обязательное | Значение |
|---|---|---:|---|
| `label` | string | да | Человеческое название позиции для КП. |
| `price_retail` | number или null | да | Розничная цена. Для `on_request` может быть `null`. |
| `price_dealer_ru` | number или null | зависит от класса | Дилерская цена РФ. |
| `discount_pct` | number или null | зависит от класса | Процент дилерской скидки, если применим. |
| `price_class` | string или отсутствует | зависит от класса | Класс расчёта цены. |
| `applies_to_lengths` | array[number] | нет | Длины весов, к которым применима опция. |
| `applies_to_lines` | array[string] | нет | Линейки весов, к которым применима опция. |
| `notes` | string | нет | Пояснение по источнику, допущению или ручному расчёту. |
| `dealer_note` | string | нет | Пояснение, почему дилерская цена не используется как нижняя граница. |
| `components` | object | нет | Составные части агрегированной цены. |
| `range_min` | number | для `C_manual_range` | Нижняя граница ручного диапазона. |
| `range_max` | number | для `C_manual_range` | Верхняя граница ручного диапазона. |
| `allow_customer_value` | boolean | нет | Разрешает значение “Заказчик” вместо цены. |
| `on_request` | boolean | нет | Цена по запросу, без активного ценового виджета. |

## Классы цен

Фактическое распределение по полю `price_class`:

| `price_class` | Количество |
|---|---:|
| `A_retail_and_dealer` | 20 |
| `B_retail_only` | 36 |
| `C_manual_range` | 4 |
| отсутствует (`UNKNOWN`) | 5 |

Дополнительно 1 опция имеет `on_request: true`. Она входит в
`B_retail_only` по полю `price_class`, но в runtime обрабатывается отдельно.

| Класс | Обязательные поля | Коридор цены |
|---|---|---|
| `A_retail_and_dealer` | `label`, `price_retail`, `price_dealer_ru`, `discount_pct`, `price_class` | `dealer_ru` -> `retail × 1.4`, дефолт `retail`. |
| `B_retail_only` | `label`, `price_retail`, `price_class` | `retail × 0.6` -> `retail × 1.4`, дефолт `retail`. `price_dealer_ru` и `discount_pct` могут быть `null`. |
| `C_manual_range` | `label`, `price_retail`, `price_class`, `range_min`, `range_max` | `range_min` -> `range_max`, дефолт `price_retail`, виджет `number_input`. |
| `UNKNOWN` | `label`, `price_retail`; `price_class` отсутствует | Синтетическая дилерская нижняя граница `retail × 0.92` -> `retail × 1.4`, дефолт `retail`. |
| `on_request` | `label`, `on_request: true`; цена может быть `null` | Ценовой виджет блокируется, позиция требует ручного запроса цены. |

Границы округляются до тысяч: нижние вверх, верхние вниз, дефолт — к ближайшей
тысяче внутри диапазона. Шаг виджета зависит от верхней границы: 1 000, 5 000
или 10 000.

## Как подготовить новый прайс вручную

1. Скопировать текущий `data/prices.json` в отдельный файл и менять копию.
2. Обновить `_meta.version`, `source_retail`, `source_dealer`, `valid_from`,
   `notes` и `updated_at`.
3. Для моделей сохранить ключи `model_id` и поля `retail`, `dealer_ru`,
   `dealer_discount_pct`. Если цена добавлена по аналогии или не из прямого
   источника, оставить пояснение через `data_incomplete` и `_meta.notes`.
4. Для опций сохранить стабильные `option_key`: они используются приложением и
   будущими diff/validator-инструментами.
5. Выбрать класс цены по источнику данных:
   - есть розница и дилерская цена -> `A_retail_and_dealer`;
   - есть только розница или дилерская цена не должна задавать нижнюю границу ->
     `B_retail_only`;
   - нужен ручной диапазон менеджера -> `C_manual_range`;
   - цена рассчитана без класса или временно наследует старую логику -> оставить
     `price_class` отсутствующим и добавить `notes`;
   - цены нет и требуется запрос -> добавить `on_request: true`.
6. Не удалять `price_retail` у обычных опций. `null` допустим только для
   `on_request`.
7. Не менять НДС: в проекте используется 22%, цены считаются уже с НДС.
8. Не записывать новый прайс в `data/prices.json` из UI. Файл обновляется
   вручную и через git после проверки.
